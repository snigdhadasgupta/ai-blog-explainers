Opus 5.5 is built for how coding sessions run now

Coding sessions have grown longer and far more context-heavy. Opus 5.5 is tuned for that shape of work — roughly 40% cheaper than Opus 5 on typical token-billed workloads, with the biggest savings concentrated in long, cache-heavy sessions.

The idea in five lines

  • Around 40% cheaper than Opus 5 on typical token-billed workloads, with the largest savings in long, context-heavy coding sessions.
  • Prices cut across the board — standard input and output tokens down 20%, cached-token reads down 60%; cached tokens cost about a fifth of competing models.
  • Sessions changed shape — from March to September 2026, context per request grew 2.6×, engagement ran 3.3× longer per prompt, and interruptions fell 68%.
  • A cache that survives — a one-hour cache lifetime for API users, and switching models or editing instructions no longer breaks the cache.
  • Subagents reuse the parent cache — forking a subagent leans on the parent’s context instead of duplicating it, and output runs about 30% faster than Opus 5.
So what for you

If your engineers run Claude Code in long sessions, the cheapest path now is to pick the model at session start, enable the one-hour cache, and compact before stepping away — most of the 40% saving comes from protecting cached reads, not from the lower sticker price alone.

Why a cost-optimized Opus

The way developers use Claude Code shifted

Anthropic looked at how usage changed between March and September 2026 and found sessions that are longer, denser, and more autonomous. People hand Claude more context and let it run further before stepping in. Opus 5.5 is designed around that reality: the expensive part of a modern session is re-reading large context, so the model and its pricing are tuned to make that cheap.

What got cheaper

Fewer turns, at a lower price per turn

Two things compound. The price per token dropped — standard input and output down 20%, cached reads down 60% — and the model itself tends to finish complex tasks in fewer turns than competing models, generating output about 30% faster than Opus 5. Zeta Labs reported fewer tool calls per task at nearly half the cost. Less work, each unit cheaper.

The biggest savings show up exactly where modern sessions live: long, context-heavy runs that lean hard on the cache.
