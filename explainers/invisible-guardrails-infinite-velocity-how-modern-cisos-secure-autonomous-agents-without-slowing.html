Invisible guardrails, infinite velocity

Autonomous agents now analyze portfolios, review contracts, and execute workflows end-to-end. Box’s Manoj Asnani and Bain Capital CISO Mark Sutton argue the security playbook of “block it” is obsolete — and that safe speed comes from getting the content layer right.

The idea in five lines

  • Blocking backfires — banning AI doesn’t stop adoption, it pushes it into the shadows where data leaks and security loses all visibility.
  • The threat model moved — the risk isn’t just hallucination anymore; it’s what an agent can access and do with tools, APIs, and persistent memory.
  • Prompt injection is structural — like phishing, it’s permanent; design data boundaries so a tricked agent has no blast radius rather than waiting for a patch.
  • Governance can’t sit with builders — non-technical staff spin up agents in hours, so the content platform must enforce permissions and containment by default.
  • Get the content layer right — classify the crown jewels, make every agent inherit the user’s permissions, and keep a governed system of record with audit and DLP.
So what for you

Before you scale an agent pilot, confirm one thing: each agent inherits the requesting user’s permissions and cannot reach content that user can’t. Then classify your most sensitive data first — that is where your containment budget should go, not on blanket bans that just create shadow AI.

The mandate shift

The department of “No” is now the dangerous option

For decades, the security reflex to an unvetted technology was simple: block it. In the era of autonomous agents — which Box and Bain Capital’s CISO frame as 5× to 10× operational leverage — that reflex isn’t just obsolete, it’s dangerous. Blanket domain bans don’t stop AI adoption; they drive it underground. Under deadline pressure, an analyst who realizes an external agent can do in ten minutes what used to take three days will paste confidential data into an unsanctioned personal tool on an unmanaged device.

Whenever you erect an arbitrary wall in front of high-value productivity, you don’t actually stop adoption — you simply blind yourself to it.

The fix is to provide sanctioned, secure, friction-free pathways so seamless that employees have zero incentive to wander off-platform. Maturity doesn’t make incidents disappear — it makes them visible, measurable, and manageable.

A new threat model

From “is it accurate?” to “what can it do?”

The first wave of enterprise-AI anxiety centered on model accuracy — is the LLM hallucinating? In the agentic era the threat model has fundamentally changed. Agents are no longer passive text generators; they have tool-use capabilities, API integrations, persistent memory, and the power to execute actions across enterprise systems. The questions that now keep CISOs awake are about access and authority, not just output quality.

Compounding this, low-code and natural-language platforms let non-technical staff in sales, HR, or finance build custom agents in hours. They rarely possess deep training in permission boundaries or data classification — so the responsibility for containment cannot sit on the builder’s shoulders. The platform itself has to enforce entitlements by default, regardless of who configured the agent.

You can’t expect an operations lead to perform threat modeling on a Friday afternoon before deploying a workflow. The content platform has to enforce native entitlements and containment by default.

The structural risk

Prompt injection is phishing, not a bug

When an agent reviews an incoming invoice, a support attachment, or a counterparty contract, that document becomes an executable input surface. If it hides adversarial instructions, an unconstrained agent can be tricked into exfiltrating data or altering records. There is no “magic patch”: as long as models interpret unstructured natural language as both input and instruction, this risk is architectural and permanent. The defensive posture is the same as for phishing — assume hostile inputs will arrive, and design boundaries so the agent simply lacks the blast radius to do catastrophic damage. The four questions a modern CISO asks of every agent:

Access

Which data can it reach?

What systems and data sources can this agent touch — and whose permissions and security context is it inheriting when it queries repositories?

Authority

What can it do?

What specific actions is the agent authorized to take on behalf of the user or the company — and what happens when it meets malicious instructions inside a document?

The playbook

Tiered governance on a unified content layer

The antidote is foundational: know where your crown jewels live, classify your content, and minimize the blast radius. “Enterprise AI is only as safe as the data architecture underneath it.” Box frames the model as a three-part promise — all your content, any AI agent, deployed with confidence — delivered through three controls.

Figure 2 · Three controls that turn AI velocity into safe velocity
A

Auto-classify & contain

AI classification flags IP, PII, and regulated records, so strict containment wraps the crown jewels while general repositories stay low-friction for experimentation.

B

Native permission inheritance

Every agent executes inside the authenticated user’s permission boundary — never superuser. If the user can’t open a document, neither can their agent.

C

Headless, multi-model

Run any model against a centralized secure system of record that guarantees audit trails, DLP, and zero-retention — no lock-in to one provider.

↻ Governance lives in the content layer, so it holds no matter which model or builder sits on top.

The CISO’s legacy in the autonomous era

Success won’t be measured by how many tools you blocked or how long projects stalled in review — but by how quickly and safely you let the business lead. Classify the crown jewels, enforce least-privilege action boundaries, and make a governed content layer the single source of truth before you scale agent deployments.
