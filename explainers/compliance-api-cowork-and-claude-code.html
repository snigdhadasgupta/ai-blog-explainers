Compliance API Now Covers Cowork & Claude Code

Security and compliance teams already pull Claude chat sessions for audits and eDiscovery. Now the same Compliance API reaches into Cowork — desktop, web, and mobile — and Claude Code in the CLI and desktop app. One interface, more surfaces, no new logging to deploy.

The idea in five lines

  • Coverage extends to Cowork (desktop, web, mobile) and Claude Code (CLI and desktop) — in beta for Claude Enterprise customers.
  • Same interface you know — pull those sessions through the identical Compliance API you already use for Claude chats, using your existing access key.
  • Additive, not disruptive — nothing changes about the data you pull today; the new endpoints only add surfaces.
  • Full session records — each returns a server-hosted transcript of prompts, responses, tool calls, skills, and artifacts, plus verified user metadata.
  • Fits your stack — no separate integration to build, and it runs alongside any OpenTelemetry export you already have.
So what for you

If your organization runs Claude Code or Cowork, your security team can now fold those sessions into the same audit and eDiscovery workflow as chats. Check whether the Compliance API is enabled for your org and query the new session endpoints — rather than standing up separate logging for each surface.

Why the gap mattered

The blind spot was the agentic surfaces

Compliance and security teams lean on the Compliance API to see how Claude is used across an organization — for audits and eDiscovery — without deploying separate logging infrastructure for every surface. Until now, that view stopped at chats. Cowork and Claude Code sessions, where a lot of the real, multi-step work happens, sat outside it.

Extending coverage closes that gap: those sessions now show up alongside Claude chats, in the same place your reviewers already look. The change is deliberately conservative — the new endpoints are additive, so existing pulls behave exactly as before.

Compliance and security teams can pull session content and metadata from Cowork and Claude Code through the same Compliance API interface they already use for chats.

How it works

One consolidated session record

The new session endpoints return a consolidated, server-hosted transcript for each Cowork and Claude Code session — so prompts, responses, and tool activity come back together in a single record rather than scattered across events. Each record carries two kinds of data.

Figure 1 · What a session record contains
Session content

What was said and done

Prompts and responses, the content of tool calls (web and MCP), and skills and artifacts content — all captured as transcript text in one place.

Session metadata

Who, where, and when

Verified user ID and email, organization ID, session and per-message IDs, and timestamps — the fields an audit or eDiscovery request actually turns on.

↻ Same Compliance API interface, same access key — the record just now spans chats, Cowork, and Claude Code.
The fine print

What the beta does and doesn’t include

Not yet covered

Some surfaces are out of scope

The beta excludes Claude Code on the web, Claude Code accessed through the Claude Platform, and sessions run on Amazon Bedrock, Google Cloud’s Vertex AI, or Microsoft Foundry. Plan your coverage map around those gaps.

Coexists with

Keep your OpenTelemetry running

Organizations already exporting OpenTelemetry data can keep it going — the Compliance API works alongside it with no additional infrastructure required on your side.

Getting started

Coverage for Cowork and Claude Code is available today, included with the Compliance API using your existing Compliance Access Key — there’s no separate integration to build. If it’s already enabled for your organization, query the new session endpoints directly. If not, review the Compliance API documentation to enable it.
