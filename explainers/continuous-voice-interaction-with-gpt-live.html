How OpenAI Built Realtime Voice for GPT-Live

Voice AI used to wait for a tiny “turn detector” to guess when you were done talking. GPT-Live throws that out: a full-duplex model that listens and speaks at once, splits talking from thinking, and starts a session in a single network round trip.

The idea in five lines

  • The turn detector is gone — GPT-Live’s voice model is full-duplex, listening and speaking at the same time, so handoffs feel immediate instead of waiting on a guess about when you finished.
  • Talking is split from thinking — the live model keeps the conversation flowing while it delegates deeper reasoning and tool use to a frontier model like GPT-5.5 on a separate asynchronous path.
  • The media path is sacred — audio moves on a dedicated fast lane (rewritten in Go, carried over WebRTC), so a slow tool call can delay its own result but can never stall speech.
  • Long calls never pause — stateful inference with seamless model-instance handoffs and background context compaction keeps hours-long sessions going without an audible gap.
  • Sessions start in one round trip — a new open handshake, WARP, collapses WebRTC startup from six network round trips to one, so a call can begin from a single UDP packet.
So what for you

If you’re evaluating voice AI for support, field, or agent workflows, judge it on responsiveness under real conditions, not the demo transcript — latency by geography, behavior on long calls, and how gracefully it keeps talking while a reasoning model works in the background. Those are the failure points that decide whether a voice agent feels natural in production.

Why voice kept feeling laggy

Turn-taking was the bottleneck

Earlier voice systems inherited the turn-based rhythm of text models: a tiny turn-detector model had to decide the moment you stopped speaking before the large model could even begin. Guess too soon and it cuts you off; guess too late and the reply feels sluggish. Humans hand off the floor in a fraction of a second, and detector-based systems simply couldn’t keep up.

GPT-Live, OpenAI’s third-generation voice system, removes the detector from the audio path entirely. The voice model is full-duplex — it can listen and speak at once — so the model itself, not a separate gatekeeper, controls the conversation. Audio simply flows in and out.

The system’s primary job is to sustain an uninterrupted media loop. Everything heavier — reasoning, tools, persistence — happens off the live path.

The core design move

Talking and thinking, split apart

GPT-Live gives fast, natural responses on its own, but when a question needs real reasoning or a tool call, it delegates to a frontier model in the background — without interrupting the flow of speech. That clean split between “talking” and “thinking” is what lets one system feel both responsive and smart. It’s also the foundation for ChatGPT Voice’s move into agentic work: controlling your computer and coordinating your agents by voice.

Async delegation

Deeper work, off the live path

A slow search or tool call runs behind an asynchronous boundary. The voice model can keep the exchange moving while a frontier model reasons, then fold the result back in when it’s ready.

Discrete turns

Clean messages from messy speech

The rest of ChatGPT still needs turns, so the server reconstructs discrete messages from overlapping speech — keeping a speculative live view for the UI and an authoritative record for analytics and safety.

How the pipeline holds together

The live path stays sacred

Any delay in transport, processing, or inference can become an audible pause. So OpenAI separated the fast media loop from all application logic: audio streams between the client and the voice model on a dedicated path, while delegation and tools sit behind an async RPC boundary that can never block the audio.

Rewrite

Go instead of Python asyncio

Moving the media frontend and inference logic to Go smoothed frame delivery so much that the new system’s p95 matches the old system’s p50 — the median made routine.

Handoff

Seamless instance switches

When an instance must change, a replacement is warmed with the current context and run in parallel, then cut over — so scaling or migration never interrupts the call.

Compaction

Long calls that fit the window

As context outgrows the limit, it’s compacted on a spare instance in the background and swapped in — heavy work kept off the live path, so the conversation never misses a beat.

Responsiveness from the first packet

A faster handshake, proven on real traffic

Vanilla WebRTC needs a surprising number of handshakes before media can flow. OpenAI built the WebRTC Abridged Roundtrip Protocol (WARP), a set of backward-compatible, open improvements it’s advancing through the IETF, plus “Instant Connect” to move the SDP exchange off the critical path. Then it validated the whole system by silently shadowing a growing share of real ChatGPT Voice traffic before letting GPT-Live speak to anyone.

The shadow test reframed the hard questions. Capacity wasn’t “how many requests can a GPU handle?” but “how many concurrent sessions can stay on schedule?” — because open voice sessions send frames continuously and saturate CPU-side handlers before the GPU. Geography became first-order: distant capacity adds delay at every step, so rollouts were validated alongside regional traffic steering. And long, realistic session lifecycles surfaced bugs — memory pressure, reconnect races — that short load tests never would.

The takeaway for anyone shipping voice

Natural voice isn’t one model — it’s a system tuned for responsiveness at every layer: a full-duplex model on a protected media path, reasoning delegated asynchronously, and a transport handshake stripped to a single round trip. If you’re building or buying voice agents, test the seams — long calls, distant users, mid-sentence delegation — not the happy-path demo.
