Claude Security Now Scans Continuously and Tracks Fixes

Claude Security now keeps up with your repositories as code changes, tracks each finding until it's fixed, learns from the context your team adds, and connects to your tools through an API and MCP. Available in public beta for Claude Enterprise.

The idea in five lines

  • From one-time scan to always-on — connect repos via the GitHub app or an access token; Claude runs a deep baseline scan, then re-scans changes on a cadence set by their risk and complexity.
  • Findings track themselves — an issue is marked fixed when the fix lands — in Claude Code or anywhere else — and reopens automatically if it comes back.
  • It learns your context — each project has a knowledge base and an editable threat model generated from the code; later scans use it to flag what matters and skip risks your environment already handles.
  • Severity with an exploit path — every finding is rated against your threat model and explained with how an attacker could reach the vulnerable code, sometimes with an attack-path diagram.
  • API and MCP — list, resolve, and reopen findings with a scoped token and webhooks — or pull up a finding in Claude.ai or Claude Code, fix it, and mark it resolved in one session.
So what for you

If you're on Claude Enterprise, point it at your highest-risk repos first and let the baseline scan plus fix-tracking replace the spreadsheet you use to chase vulnerabilities — the $25K/month credits through Dec 31 make a pilot effectively free to try.

The shift

A snapshot became a live feed

Claude Security entered public beta in April; since then thousands of organizations have used it to find over a million vulnerabilities. The change now is from point-in-time scanning to continuous monitoring with fix-tracking. It's powered by the full family of models, including Claude Mythos, with no Cyber Verification Program access required.

Claude Security scanned our code once to set a baseline. Now it keeps up as our code changes. — Jake Meredith, Product Security, Gusto

Why it matters

Scanning that goes stale isn't security

A scan that's accurate only until the next commit is a snapshot, not a safeguard. Continuous re-scanning, automatic fix-tracking, and multi-repo projects keep the picture live — and because a project can hold several repositories, it can catch issues between services, such as a backend that trusts input a client was supposed to validate. Findings route to the teams that own the code.

Knowledge base

Your context, written down

Each project describes deployment, applicable security policies, and anything a new security engineer would need to know.

Threat model

Generated, then editable

It builds a threat model from the code that your team reviews and edits; later scans use it to flag what matters and skip risks already handled.

Severity

Rated with an exploit path

Each finding carries a severity judged against the threat model and an explanation of how an attacker could reach the code — sometimes an attack-path diagram.

Wiring it into your tools

API, MCP, and role-based access

API + webhooks

Automate the workflow

The API lists and reads projects and findings, resolves or reopens them, and manages projects and repos. A personal access token can only see and change what the user can; webhooks notify external systems when a new finding lands.

MCP connector

Fix it in one session

Claude Security is an MCP connector in Claude.ai and Claude Code, so an engineer can pull up a finding, ask Claude about it, start the fix, and mark it resolved without switching tools. New role-based access controls decide who can view, triage, or create projects.

Getting started

Admins enable it in the admin console and set who can view, triage, and create projects. Claude Enterprise customers get $25,000 in free usage credits each month for two months, applying to usage through December 31, 2026.
