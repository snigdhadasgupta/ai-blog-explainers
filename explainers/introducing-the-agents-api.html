OpenAI’s Agents API: Orchestration as a Service

The Agents API (public beta) exposes the same orchestration that powers Codex: define task, model, tools, and environment in one call, and OpenAI handles context management, sandboxes, and multi-agent delegation — you pay only for tokens and tool use.

The idea in five lines

  • One call to a live agent — specify task, model (gpt-6-astra), tools, and environment in a single API call — no bespoke orchestration loop.
  • Bring your own compute — run in OpenAI-hosted sandboxes or self-host via Modal, Cloudflare, E2B, Vercel, Oracle, and others.
  • Context managed for you — the harness compacts earlier context near the limit, so workflows span multiple context windows automatically.
  • Subagents in parallel — delegate subtasks to parallel subagents, each with its own context and a configurable concurrency cap.
  • Efficiency built in — tool search loads only relevant definitions and programmatic tool calling runs in parallel.
So what for you

If your team is hand-rolling agent loops — retry logic, context trimming, sandbox plumbing — evaluate whether a managed orchestration layer removes code you don’t want to own. The trade is less control over the loop for far less infrastructure; prototype one workflow on it before committing.

What changed

The hard part of agents was never the model

Calling a model is easy. The difficulty in production agents is everything around it: managing context as sessions grow, running code in a safe sandbox, retrying failures, and coordinating subagents. OpenAI packaged the orchestration that already runs Codex and exposed it as an API, so teams can define an agent instead of building the loop.

Define task, model, tools, and environment in one call — and pay only for tokens and tool usage, with no additional API fees.
