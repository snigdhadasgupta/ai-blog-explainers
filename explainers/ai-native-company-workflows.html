Turning Workflows Into Operating Capability

The gap between frontier firms and everyone else is widening — the top 10% of AI users now generate 8.3× the output per person. Three AI-native startups show the moves behind that lead: teach an agent a stable process, give it persistent context, then let it carry work into tested action.

The idea in five lines

  • The lead is compounding — frontier firms now generate 8.3× as many output tokens per active user as typical firms, up from 2.6× in January.
  • Basis teaches the agent — a reusable onboarding “skill” with a clear trigger and definition of done cut first-day onboarding from two hours to 30 minutes.
  • Clay gives it a home base — a persistent workspace and per-account subagent keep scattered deal context current overnight, saving a seller ~an hour of triage a night.
  • Exa carries it to action — Codex monitors for integration opportunities, gathers context, opens pull requests, runs tests, and preps updates, with humans reviewing before anything ships.
  • The reusable playbook — pick one consequential workflow, define the outcome and measure, write the agent’s job description, build the human system, and package what works.
So what for you

Pick one end-to-end workflow that repeats often and matters enough to justify redesign — then write the agent a real “job description” (trigger, required context, tools, where it must stop for human review) rather than bolting AI onto the current process. Depth of use, not volume of prompts, is what separates the leaders.

The pattern

A three-step progression toward capability

OpenAI’s Enterprise Signals data shows AI moving from assistance to execution at sharply different speeds. Leading firms connect agents to company context and tools, delegate more substantive work, and make successful workflows easy to repeat. The three companies below differ in what they do, but the arc is the same: teach a stable process, add persistent context as work changes, then let the agent take an opportunity into bounded execution.

In each case a person still decides what matters at the point of action — which deals to push, which integrations to build, what an agent may commit to. Tests and review points keep the agent’s work visible before it ships, and the exceptions reveal where the workflow needs sharpening.

The operating playbook

Six steps to experiment now and scale what works

01

Choose one value surface

Start with an end-to-end workflow where a strategic priority, systems, handoffs, controls, and measurable stakes meet — one that repeats often enough to learn from.

02

Define the outcome + measure

Name the owner, KPI, baseline, and guardrails. Track depth (completed tasks, connected tools, exceptions) and value (cycle time, quality, cost, revenue, risk).

03

Write the agent’s job description

Specify the trigger, outcome, required context, tools, permissions, how persistently it should work, the evidence it must produce, and where it stops for review.

04

Build the human system

Put the people closest to the workflow in the design loop. Name who owns the outcome, domain logic, access, adoption, and daily use.

05

Make it visible + reusable

Give employees room to test, then package what works as skills, plugins, or shared workspaces. (OpenAI notes early-career staff sent 13 more messages/week than execs six months in.)

06

Carry the pattern forward

Preserve the context, permissions, evaluations, review points, owners, and measures that worked, and apply them to the next value surface.

What to do about it

Don’t chase prompt volume. Choose a single consequential workflow, give the agent a written job description with explicit stop points for human review, measure both depth and value, and turn the strongest experiment into a reusable skill others can start from.
