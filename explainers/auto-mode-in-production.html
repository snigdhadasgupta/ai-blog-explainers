Auto Mode, Running in Production

Nuro, Gusto, and Garner Health run Claude Code’s auto mode as their everyday default — swapping permission fatigue for longer autonomous runs, while keeping a human on the calls that matter.

The idea in five lines

  • Auto mode is the default — a classifier vets each tool call instead of asking you to approve every command.
  • 9× longer between interruptions — across all Claude Code usage, sessions pause far less — enough to leave agents running for hours.
  • Nuro runs overnight agents — that hill-climb evaluation metrics on the autonomous-driving stack and return finished PRs by morning.
  • Gusto ended permission fatigue — roughly 10% of sessions since mid-May hit a classifier denial — evidence it blocks at the right moments.
  • Garner standardized its SDLC — for all 550 employees on auto mode, dropping hand-curated command allowlists.
So what for you

If your engineers are already clicking “bypass permissions” to move faster, auto mode is the safer middle path. Pair it with a few hard-deny rules and real telemetry before you roll it out team-wide.

Why teams switched

The speed-vs-safety tradeoff, resolved

Reviewing every command keeps a human in the loop, but once sessions stretch to hours or run in parallel, that oversight becomes the bottleneck. Skipping permission checks entirely is faster — and it’s also how prompt injection, scope drift, and the occasional deleted production resource slip through.

Auto mode closes most of that gap. In internal evaluations the classifier caught more dangerous actions than developers did clicking through prompts, and the result held up under third-party red-teaming. Because sessions pause less often, Claude works about 9× longer between interruptions than under the previous default.

“I use auto mode for 100 percent of my coding work — most of the time I open three or four sessions in parallel and just check in when I need to.” — Kai Zhou, Staff Software Engineer, Nuro

Three production patterns

What it unlocks, team by team

Nuro

Overnight research agents

Long-running agents study evaluation false-negatives, draft proposals, run experiments, and iterate against a measurable signal. “I kicked off an agent at 10 p.m.… it gave me three PRs in the morning.”

Gusto

Speed without the fatigue

Adopted to end the permission fatigue pushing engineers toward bypass. Cross-repo work runs uninterrupted; ~10% of sessions since mid-May include a classifier denial — blocking at the right time, not everywhere.

Garner Health

A standardized SDLC

Pushed as the default to all 550 employees via managed settings. A plugin of standard skills lets agents research, pressure-test assumptions, and implement — pausing only when they need context they can’t find.

Where humans stay in the loop

Auto mode runs inside guardrails, not instead of them

None of these teams run auto mode unconstrained. The classifier makes its calls inside boundaries the teams set, and every rep keeps a manual override for high-stakes work.

Hard limits

Deny the irreversible

Nuro denies recursive deletes outright in settings. Both Nuro and Garner configure auto mode not to approve actions that message other people — Slack, email — so a human owns anything that leaves the team.

Step out for prod

Review the risky calls

Reps switch back to interactive mode for PR reviews and for production infrastructure — Terraform, AWS, live API calls. “Ultimately, you’re still responsible for what happens.”

Defense in depth

Layers around the agent

Gusto routes MCP traffic through a governed proxy with tool guards and prompt inspection, so agents already work with tightly scoped permissions before auto mode weighs in.

Telemetry

Don’t fly blind

Garner’s advice: build standard workflows and keep telemetry. “If everyone builds their own workflows and we have no telemetry, that would be very dangerous.”

Thinking about turning it on?

Start with a few hard-deny rules for irreversible and off-network actions, keep a human on anything that touches production or communicates externally, and instrument sessions so you can see where the classifier is blocking. Then let longer, uninterrupted runs do the heavy lifting.
