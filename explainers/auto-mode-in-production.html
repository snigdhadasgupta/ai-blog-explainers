Auto Mode in Production

Auto mode resolves agentic coding’s oldest tension — speed versus safety. Three teams shipping real software — Nuro, Gusto, and Garner Health — explain why a safety classifier that vets every command became their daily driver, and where they still take the wheel back.

The idea in five lines

  • Auto mode vets every command — a safety classifier approves routine tool calls and blocks the destructive ones, so agents keep working without a human clicking through each prompt.
  • It ends the speed-versus-safety tradeoff — Anthropic’s classifier caught more dangerous actions than developers did by hand, and sessions now run 9× longer between interruptions.
  • Three teams made it the default — Nuro, Gusto, and Garner Health run auto mode as their daily driver across autonomous-driving, payroll, and healthcare codebases.
  • The unlock is long-horizon work — agents keep going after hours; one Nuro run went from 10 p.m. to 5 a.m. and returned three pull requests by morning.
  • Guardrails still do the heavy lifting — deny-lists, governed tool proxies, and switching back to manual review for production infrastructure keep the autonomy inside safe bounds.
So what for you

If your teams are piloting agentic coding, let auto mode carry the routine and reserve human review for the irreversible — deny the handful of catastrophic commands outright, route tools through a governed layer, and keep a person in the loop for production infrastructure and anything sent to other people.

The tradeoff it resolves

Speed or safety — auto mode stops making you choose

Reviewing every command keeps a human in the loop, but once sessions stretch to hours or run in parallel, that oversight becomes the bottleneck. Skipping permission checks entirely is faster — and it’s also how prompt injection, scope drift, and the occasional deleted production resource slip through. Auto mode closes most of that gap: a classifier evaluates each action and blocks the ones that look dangerous, while everything routine flows through untouched.

In internal evaluations, the classifier caught more dangerous actions than developers did when clicking through permission prompts by hand, and its performance held up under third-party red-teaming. Because sessions pause less often, Claude works 9× longer between interruptions — measured across all Claude Code usage.

“I use auto mode for 100 percent of my coding work. Most of the time, I open three or four sessions running in parallel and just check in when I need to.” — Kai Zhou, staff software engineer, Nuro

Three deployments

Same default, three very different workloads

Nuro Physical AI · L4 autonomous driving

Auto mode powers long-running research agents that hill-climb the evaluation metrics behind the driving stack — studying false negatives, drafting proposals, and running experiments overnight against a clear, measurable signal. Engineers deny the most dangerous commands, like recursive deletes, outright in their settings and lean heavily on skills, so the classifier makes its calls inside fixed guardrails.

Gusto Payroll & HR platform

Adoption began as a proactive security upgrade against permission fatigue. Unattended jobs — like compiling daily notes from GitHub, Slack, and Jira — now run on their own, and about 10% of session transcripts since mid-May included an auto-mode denial, evidence the classifier blocks at the right moments without dragging on legitimate work. MCP traffic is routed through a governed proxy with tool guards and prompt inspection before auto mode ever weighs in.

Garner Health Healthcare technology

Claude Code reached all 550 employees, with staff encouraged to automate the most repeatable parts of their week. A standardized software-development lifecycle — shipped as a plugin of skills — has an agent explore context, commit context files to the repo, run “antagonistic research” to pressure-test its own assumptions, then implement, pausing for a human only when it hits a gap it can’t fill.

Defense in depth

Why “let it run” isn’t the same as “no controls”

Intent check

The classifier watches for drift

Beyond blocking destructive commands, it checks that each action still lines up with your original request — the mechanism that catches prompt injection and scope drift. “When it stopped me, it made sense and explained why. It was drifting from what I’d originally asked,” said Gusto’s Chad Kunsman.

Hard limits

Deny-lists sit below the classifier

The riskiest commands — recursive deletes and the like — are denied outright in settings. The classifier makes judgment calls inside those boundaries, not in place of them, so a single bad inference can’t reach the catastrophic actions.

Scoped first

Tightly permissioned before it starts

Gusto routes MCP traffic through a governed proxy layer with tool guards and prompt inspection, so agents already hold narrowly scoped permissions before auto mode weighs in — defense in depth, not a single gate.

Not on your behalf

No messaging other people

Both Nuro and Garner configured auto mode not to approve actions that communicate with other people — Slack messages, emails — so the agent never speaks under your name. “I don’t like Claude to just act on my behalf when I’m communicating with another person,” said Garner’s Evan Magnussen.

Human still in the loop

The work engineers won’t hand to a classifier

Take the wheel

Production infrastructure

For Terraform, AWS, or direct POST calls against live APIs, Gusto’s Chad Kunsman switches to accept-edits and verifies each tool call by hand. “You have to weigh the time you’re saving against what it could reasonably get wrong, and how catastrophic that would be. Ultimately, you’re still responsible for what happens.”

Take the wheel

Speaking for the team

Nuro’s Kai Zhou flips back to interactive mode when Claude reviews a pull request on his behalf. Anything that goes out under his name — or touches another team’s work — gets a human read before it ships.

Rolling it out? Lean in — with controls

Garner’s advice for enterprises: empower engineers, but build the telemetry and standardized workflows first. “Because we have the telemetry, because we’ve built out workflows that are relatively standard, we have much more confidence.” Start with deny-lists and a governed tool layer, then let auto mode carry the routine.
