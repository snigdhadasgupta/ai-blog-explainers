Source control at agent scale

Anthropic’s agents now merge tens of thousands of code changes a day. Git — built for offline, distributed, human developers — started fighting back. So a seven-person team built Scion, an always-online, server-centric version control system, and moved the monorepo off git in five months.

The idea in five lines

  • Coding stopped being the bottleneck — the constraint is now the developer infrastructure built for human scale: source control, builds, and CI.
  • Merge volume exploded — from around 2,500 code changes merged per day in May 2026 to over 30,000 per day by September, as agents write most of the code.
  • Git’s offline-first design fought back — an almost 100 GB history and ~25 million checkouts a day meant naive fetching would top 600 PB of traffic daily.
  • They built Scion — an always-online, server-centric system where commits, merges, and rebases happen on the server and the client stays thin and sparse.
  • Seven people, five months — the result runs on ~200× less infrastructure, checks out in seconds not minutes, and freed 25% of CI CPU. (All figures self-reported.)
So what for you

If agents are writing a growing share of your code, the bottleneck moves downstream — to the review, CI, and source-control tooling built for human throughput. Watch those systems for strain before volume forces the issue, even if your scale never approaches Anthropic’s.

Why this happened

When the typing stops being the hard part

Anthropic’s monorepo was built on git’s assumption that each developer works offline on a full local copy. But its main clients are no longer people at laptops — they are agents and automated jobs that are always online and prolific. Once Claude could write code faster than humans could merge it, the demand for merging became, in the team’s words, practically infinite: every bottleneck removed immediately led to even more code.

“At Anthropic, coding is no longer the bottleneck. The bottleneck, now, is all of the developer infrastructure built for human scale: source control, builds, and CI.”

The team is candid that engineers’ role shifted. They still review every change to the system, but they examine the intent of a change rather than reading every line — and “very often, the role of the engineers was to tell Claude ‘no.’”

For context, the monorepo’s main-branch history is almost 100 GB and a compressed working copy tops 25 GB; CI alone performs on the order of 25 million checkouts a day. Naively fetching that with git would have been over 600 PB of traffic daily. At peak, Anthropic ran several hundred internal git mirrors to cope — which grew unmanageable as the merge rate climbed. All figures are Anthropic’s own, self-reported.

How it works

Inside Scion: thin client, heavy server

Figure 1 · Scion’s four design inversions vs. git
1

Always online

Clients fetch immutable objects on demand; the server is always reachable, so there is nothing to push.

2

Server does the work

History, blame, commits, merges, and rebases all happen server-side. The client computes almost nothing.

3

Service, not a repo

Every query is an API, so most CI jobs, bisect, and revert pipelines need no local repository at all.

4

Optional working copy

Checkouts are sparse and virtualized — only the requested directories, materialized on demand.

↻ The unit of work is a “changeset” in a write-ahead log — cheap, incremental, and lock-free, created on the server.
Topology

Strictly tiered caches

A per-node daemon talks only to regional caches, which talk to authoritative servers over Spanner and cloud storage. Over 99% cache-hit at each tier, and a cache failure can’t overwhelm upstream.

Merging

No global repo lock

A traditional merge queue “doesn’t make much sense at agent scale,” so Anthropic leans on post-merge and pre-deploy testing. Conflicts happen — but Claude typically fixes them faster than humans can spot them.

Derived data

One generic mechanism

Blame, path history, commit-graph skip lists, and search are all computed recursively from changesets — so new derived types are easy to add and can be eager or deferred.

Read the fine print

The caveats Anthropic states plainly

Not a product

“Not a replacement for git”

Scion only makes sense for truly enormous monorepos — tens of thousands of engineers or swarms of agents. It needs its own code review, code search, and CI, and Anthropic can spend tokens on internal tooling in ways few businesses would.

Still steered

Agents violate constraints

Agents “will sometimes violate core system constraints,” and adversarial review can be myopic, leading to over-engineering. Engineers still steer the work — the contribution is an early view of how agentic development stresses these systems.

Anthropic frames Scion’s narrow concepts — server-side RPCs, novel server architectures, standardized forge APIs — as ideas others might apply to git without leaving git’s model. The forecast: this class of problem becomes “more commonplace over the next six to 12 months” as the software lifecycle meets the AI exponential.

What to watch on your own roadmap

You don’t need Scion — but you may soon feel the same pressure. As agents open more pull requests, the questions shift from “can we write it?” to “can our review, CI, and version control keep up, and can a human still vouch for intent?” Instrument those systems now.
