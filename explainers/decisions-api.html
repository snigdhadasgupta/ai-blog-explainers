The idea in five lines

  • Bounded answers, not prose — you define a question and its allowed answers, supply context as text, images, or JSON, and the API returns one of three typed results an app can act on.
  • Built for the hot path — now generally available on GPT-6 Luna and up to 10× faster than Luna through the Responses API, so decisions can sit inside live workflows.
  • Three answer types — a predicate (probability a condition is true), a choice (one of your options), or a score (a rubric rating).

  • Real speedups reported — customers cite 3× to 40× faster at comparable accuracy, and 30–90% lower cost per call.
So what for you

Audit the small, repetitive judgment calls buried in your product — routing, triage, risk checks, “should the agent continue or ask?” — that you’re currently paying a full chat model to make. Those are exactly what a bounded-decision endpoint is cheapest and fastest at, and moving them off the chat path often matters more to latency and spend than any prompt tweak.

The problem

Small decisions are where latency and cost hide

Inside any real workflow, an application or agent makes many small decisions: how to classify an input, where to route a request, which action to take next. Individually they’re trivial. At scale, their latency and cost add up — and if each one runs through a general chat completion, you pay full freight for a yes/no.

The Decisions API focuses a frontier model’s intelligence on questions with bounded answers, so applications and agents can decide in near real time.

It’s now generally available, built on GPT-6 Luna, and reported at up to 10× faster than Luna through the Responses API. You pay only for input tokens — there are no output-token charges — at $0.10 per million input tokens and $0.01 per million cached.

What it returns

Three bounded answer types

Predicate

Is this true?

Estimates the probability a condition holds — e.g. whether a product has visible damage. Result: a number from 0 to 1.

Choice

Which option?

Selects one of your predefined options — e.g. continue, retry, or ask for clarification. Returns the chosen value plus probabilities and confidence.

Score

How much?

Rates an input against ordered levels in a rubric — e.g. severity of damage. Returns a probability-weighted average of the level indices.

How it works

Voice

Fast decisions inside live GPT-Live conversations

In GPT-Live, you add a decision to session.triggers — for example, a choice question that picks an avatar’s reaction (neutral, happy, sad, concerned) from the user’s latest message. GPT-Live emits a decision.event; the app reads the selected value and reacts. The same pattern lets a support agent decide, mid-conversation, whether to ask a clarifying question, route the request, or escalate. Test questions in the Decisions Playground before wiring them in.

Where to put it

Reach for the Decisions API wherever a model is making a bounded call at volume — classification, routing, risk scoring, next-action selection in agents and live voice. Process in the US or EU, keep lower-confidence cases flowing to humans, and pay only for the input you send.
