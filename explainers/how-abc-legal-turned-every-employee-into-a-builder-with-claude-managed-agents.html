ABC Legal: Every Employee an Agent Builder

A 1,100-person legal document company moved AI from scattered desktop scripts to a governed fleet of 50+ always-on cloud agents — each one defined as code, versioned in git, and improved through the same pull requests its developers already use.

The idea in five lines

  • Adoption came first — teams across ABC Legal started automating their own daily tasks the moment Claude Enterprise landed, without being asked.
  • Then came the infrastructure — agents were moved off personal laptops into Claude Managed Agents: always-on, in the cloud, with one audit and billing surface.
  • Every agent is code — prompt, tools, schedule, and credentials live in a git repo, so nothing changes except through a reviewed pull request.
  • Non-developers built the fleet — a 15-person committee with no engineers each shipped a working agent in a week; 50+ were running within a month.
  • Agents improve themselves — a harvester turns Slack reactions into labeled feedback and a weekly tuner drafts prompt changes as PRs a human approves.
So what for you

If your teams are spinning up AI automations, get them out of individual desktops and into a shared, version-controlled home before the fleet grows. The value isn't a clever prompt — it's being able to see every agent, review changes, and roll one back when it misbehaves.

From enthusiasm to engineering

Treat every agent like software

When CTO Brandon Fuller rolled out Claude Enterprise to all 1,100 employees, people across service of process, eFiling, marketing, compliance, and finance began automating the tasks that ate up their days — on their own. The problem wasn't enthusiasm; it was that early agents lived wherever their builder happened to put them, as scheduled tasks on individual desktops.

An agent is really just structured text — a prompt plus configuration — and anything that is text can live in a repository where the whole company can see it, review it, and improve it.

So ABC Legal defined every agent as code. An agent's prompt, tool list, schedule, credentials, and memory all go into config files in a git repository alongside the company's software. Nothing changes except through an approved pull request — which hands every agent version history, code review, rollback, and an audit trail for free. A one-week starter kit with two templates (event-driven and scheduled) means a builder never writes software: they clone the repo, copy a template, tell Claude Code what the agent should do, and merging to main deploys it automatically.

The fleet

An agent at most stages of the work

Each agent has a name, an owner, and a single job. They post what they did or recommend to Slack, where people reply in threads and react with emoji — keeping a human in the loop before anything is acted on.

Engineering

AI Code Reviewer

Reviews every pull request across four codebases with multi-model analysis, catching security bugs, performance regressions, and committed credentials. Engineers wait for its review before merging.

Operations

eFiling Rejection Diagnoser

Fires when a court rejects a filing, reads the job, checks the court's rules, and posts a diagnosis to Slack in about a minute — work that used to consume hours.

Customer

EvidenceChain Delivery Agent

Pulls matching records, retrieves each PDF with a built-in browser, and delivers to a customer's FTP daily. Built in about an hour by an account manager who'd never automated anything.

Compliance

Charvis, the service reviewer

Checks completed service jobs and now agrees with the compliance team about 98% of the time — earning trust before it acts alone.

Finance

AR-remittance agent

Parses a remittance email, builds the NetSuite payment-application file, and posts to Slack for one-click approval before importing it.

Marketing

Google Ads analyst

The mechanism

How the agents get smarter without retraining

Fuller saw Slack reaction data as a training signal going to waste. For the agents that collect graded feedback, ABC Legal uses a three-role architecture: separate agents that share one workspace, environment, and credential vault but run on different schedules. The loop turns messages in Slack into versioned, human-approved changes — it tunes the prompt and config, never the model's weights.

Figure 2 · The self-improving agent loop
1

Initial Agent

Does the work in real time as a job arrives, recording an audit trail of each action.

2

Harvester

Runs hourly or daily, sweeping Slack thread replies and emoji into labeled data points.

3

Tuner

Runs weekly, looks across everything, and drafts a prompt or config change — only drafts.

4

Human PR

A person reviews and merges the pull request. The review is the only manual step.

↻ An emoji reaction flagging a mis-routed delivery can become a merged change to that delivery's routing rules within the week.

Not every agent needs the signal: most of the fleet are single-task runners whose output no one grades. The pattern also drives "deliveries-as-code" at Docketly, ABC Legal's 50-person sister company, where all ~145 routing rulesets are single YAML files in git — so tuning a delivery means editing a file and opening a PR.

Why Claude Managed Agents

The division of responsibility that made it work

Fuller's criteria were specific: versioning, observable sessions, workspace billing, model selection, memory primitives, MCP wiring, and — most critically — no infrastructure to babysit. Anthropic's managed layer owns the execution loop, sessions, memory, console, and models; ABC Legal owns the prompt, tool list, trigger logic, audit trail, and feedback loop.

At scale

Versioning & model flexibility

Every push creates a new version with optimistic locking, so rollback is trivial. Sonnet is the default, Haiku handles high-volume fast tasks, and Opus is reserved for deeper reasoning — swapping models is a one-line change.

Wiring

MCP tools & scheduling

Agents connect to ABC Legal's own platform (100+ tools), Metabase, Slack, and Atlassian through credential vaults. Recurring agents run on cron via Bitbucket Pipelines, which already handles repo access, secrets, and billing.

Cost is governed by an efficiency ratio — value delivered against what an agent costs to run, reported back to a data warehouse in hours and dollars on every run. Agents follow a J-curve: often underwater when new and running larger models, then flipping positive as the team writes evals, moves to cheaper models, and trims tokens. Fuller's blunt advice: the hard part was the git hurdle, not the AI — and not every task deserves an agent.

The playbook, in one line each

Turn as much of the business into text in a repo as you can; start every agent with a human in the loop and let it earn autonomy; make the decision look like a pull request; invest in the feedback loop; and skip the scheduled-tasks detour — go straight to managed, governed agents.
