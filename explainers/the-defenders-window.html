The Defender’s Window

AI models can now automate parts of real cyberattacks, exposing the long tail of flaws hiding in every company’s tech debt. But the same capabilities hand defenders a decisive edge — if they move now. Greg Brockman lays out what OpenAI is doing and what every security team should do this week.

So what for you

Don’t wait for a company-wide rollout: put a capable coding-and-security agent in your team’s hands this week, point it at your highest-priority internet-facing systems, and have it triage your existing vulnerability backlog — keeping human review for consequential fixes.

The moment

Attackers just got faster — so can you

AI models developed worldwide are increasingly able to automate parts of real-world cyberattacks, making longstanding gaps — bugs buried in human-written code, forgotten permissions — easier to find and exploit. In the OpenAI–Hugging Face incident, an agentic collective autonomously penetrated both OpenAI research infrastructure and another company’s production systems, chaining previously-unknown flaws with leaked credentials.

Security is still a cat-and-mouse game, but AI may shift its economics in ways that fundamentally advantage defenders — if companies act decisively.

The tech debt of every company masks significant flaws. The same AI capabilities that help attackers also let defenders find, prioritize, and fix those weaknesses — and OpenAI is now training models specifically to write superhumanly secure code and to apply formal verification that has been intractable for humans.

A concrete example

15 minutes, 13 issues, one hour to fix

Brockman asked ChatGPT Work (using publicly available GPT-5.6) to assess the security of his simple static site. In about 15 minutes it surfaced 13 issues — unconfigured DNS records that let attackers forge email, an insecure jQuery version, Cloudflare forwarding to AWS over unencrypted HTTP. Asked to fix them, the agent spent an hour clicking through the Cloudflare control panel to configure DNS and TLS, dropped jQuery, migrated hosting, and began a phased DMARC rollout.

This is a “cyberguardian” pattern: an agent finds the long tail of issues a human wouldn’t have time or expertise to reach, then fixes them with a sensible rollout — while humans keep responsibility for the highest-impact decisions.

The playbook

What defenders should do now

Brockman’s guidance is deliberately tool-agnostic — what matters is getting capable AI into defenders’ hands, not the specific vendor. The steps below are meant to run at “turbo speed,” starting with your highest-priority systems rather than a company-wide program.

Give your security team an agentStart now

Grant a capable agentic security tool approved access to the codebases, infra configs, and docs your team must assess — don’t wait for a full rollout.

Equip it with expertiseSkills

Start from community-supported skills for static analysis, security code review, and supply-chain risk, then build your own around your architecture and threat models.

Assess your own systemsPrioritize

Run assessments first against internet-facing services, authentication flows, infrastructure-as-code, and deployment pipelines; expand as confidence grows.

Work the backlogTriage

Feed the agent scanner findings, dependency alerts, and old tickets; have it separate exploitable issues from noise and recommend what to fix first.

Incrementally automate triageRead-only first

Begin with a read-only scan of one repo, human deciding every case; move to advisory PR scanning, then live triage, then auto-closing narrow false positives.

OpenAI says the Hugging Face incident showed it had underestimated its own models’ real-world cyber capability. Its response rests on four pillars: use models (via Codex and a security plugin) to catch vulnerabilities before code ships; triage almost all initial security alerts with intelligence before humans are looped in; continuously enumerate attack paths, misconfigurations, and over-privileged identities; and invest in fundamentals — defense in depth, least privilege, network isolation, and safe patching — so that multiple independent controls must fail simultaneously for anything catastrophic to occur.

The window is open now

Open-weight models with cyber capability are only months behind the frontier, and the next is slated for release imminently. Get organizational buy-in, run tabletops, and start automating small parts of your security program before the gap closes — no company can do this alone.
