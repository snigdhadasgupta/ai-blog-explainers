The Chrome side panel is now a Cowork session

Claude in Chrome used to be a separate conversation from the apps. Now the side panel runs the same Claude Cowork session you use on desktop, web, and mobile — so a task you start in a tab can be finished anywhere.

The idea in five lines

  • One continuous session — the Claude in Chrome side panel is now a Claude Cowork session; conversations save to your history and carry across desktop, web, and mobile.
  • Skills and connectors travel — they work inside the browser, and a task started in a tab can be picked up later in the app.
  • Reaches apps connectors can’t — Claude acts inside internal dashboards, legacy systems, and vendor portals through the browser, using your existing logins.
  • An action check on autopilot — “automatically approve” runs a task without stopping, but a separate check blocks any consequential action that doesn’t match your original request.
  • Rolling out now — live on Max and Team today, reaching Pro over the coming weeks; off by default on Enterprise with admin domain controls.
So what for you

If your real work is trapped in portals and dashboards with no connector, this is where a browser agent earns its keep — collecting figures across tabs and building the output for you. Start on sites you trust, and keep the “ask before purchases or sharing personal data” guardrails on.

What actually changed

From a walled-off panel to one account-wide session

Claude in Chrome is a browser extension that lets Claude see the page you’re on and act in it — clicking links, typing, navigating, and filling forms with your existing logins. Many everyday tools connect directly to Claude, but plenty don’t: internal dashboards, legacy systems, vendor portals. The browser is how Claude reaches those.

Until now, a side-panel session was separate from the ones in the Claude apps, so context didn’t carry between them. Now the side panel runs the same Cowork session. Because sessions live with your account rather than a single device, you can start in the browser and finish somewhere else.

Ask Claude in Chrome to pull invoice amounts and dates from several vendor portals — then open the desktop app to add files from your computer and ask what changed since last month.

The risk that comes with acting in a browser

Prompt injection, and the check that guards against it

Claude in Chrome carries the same risk as any agent that acts in a browser, chiefly prompt injection: malicious actors hide instructions in web content — a page, an email, a document — that you can’t see but that can redirect Claude to take actions you never intended.

A check on Claude’s own actions

With “automatically approve” on, Claude works through a task without stopping at every step — but before anything consequential (submitting a form, sending a message, downloading a file) a separate check reviews the action against what you originally asked and blocks anything that doesn’t match.

Hard stops on irreversible actions

Claude still asks before costly or irreversible moves like making a purchase or sharing personal data. These measures reduce risk meaningfully but can’t eliminate it — prompt injection is a moving target, so new defenses are built into each model release.

Enterprise controls

On Enterprise plans, Claude in Chrome is off by default; admins turn it on and can limit it to approved domains. The guidance for everyone: start on sites you trust.

Getting started

Install Claude in Chrome from the Chrome Web Store, sign in, and open the side panel. It’s on Max and Team today and rolling out to Pro. You’ll still use the desktop app for files on your computer, and it doesn’t run on other Chromium browsers or mobile yet.
