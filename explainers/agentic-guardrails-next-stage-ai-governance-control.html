The next stage of AI governance is control

For years, AI governance meant understanding how a model produced an answer. Autonomous agents raise a sharper question: once a system can take action, how do you know what it actually did? Box argues the new standard is the ability to demonstrate control — over an agent’s authority, access, actions, and the record it leaves behind.

The idea in five lines

  • The governance question shifts — from “how did the model answer?” to “what did the agent actually do?” once agents can take action.
  • Guardrails, not brakes — an agent shouldn’t bypass controls a user already has: no reaching files the user can’t, no external shares that are blocked.
  • Match oversight to impact — reversible, low-risk actions can run autonomously; deletes, permission changes, and external publishing need a human in the loop.
  • Session governance beats activity logs — a session record shows who initiated, which agent acted, what it accessed, what was denied, and what was approved.
  • Reuse the controls you have — identity and access, classification, retention, legal hold, incident response, and audit logging must keep applying when an agent enters the workflow.
So what for you

Before you deploy an agent, verify its permissions, access limits, and sharing restrictions against the human it acts for — and require a session-level record. When an auditor, customer, or security team asks what happened, a full session trail is what lets you answer instead of stitching the story from scattered logs.

The shift

From prompts and outputs to authority and actions

As enterprises deploy agents that search repositories, retrieve documents, initiate workflows, update records, and act on a user’s behalf, it becomes less useful to think about governance only in terms of prompts and outputs. Organizations need to understand the authority an agent has been given, the information it can access, the actions it can take, and the record it leaves behind.

The next standard for agent governance will be the ability to demonstrate control — that agents operate within clear boundaries, respect existing permissions, and remain accountable to the people and systems they act for.

Practical guardrails

Autonomy you can manage

An agent shouldn’t become a shortcut around controls that already apply. If a user can’t open a restricted file, the agent acting for them shouldn’t either; if a document can’t be shared externally, the agent shouldn’t distribute it. The goal isn’t to remove autonomy — it’s to make the level of oversight reflect an action’s potential impact.

Figure 1 · Oversight should scale with impact
Low risk

Automated execution

Reversible, low-impact actions can run with limited to no human oversight.

Elevated

Checkpoints

Sensitive or ambiguous steps get a review point before they proceed.

Consequential

Human in the loop

Deleting data, changing permissions, transferring sensitive content, or publishing externally requires approval.

The record that matters

Activity logging vs. session governance

The harder challenge appears after the agent finishes. An auditor, customer, or security team may need to know which agent performed an activity, who initiated it, what it accessed, what tools it used, what it changed, and whether a person approved any part. Today those answers are scattered across application logs, identity systems, security tools, model records, and content repositories.

Activity loggingEvents

Shows that a file was opened or a permission changed — but rarely why, on whose behalf, under what task, or which controls applied.

Session governanceFull account

Shows that an employee asked an agent to prepare a customer briefing, that it accessed three permitted documents, was denied a restricted folder, and had an external share paused for approval.

A useful session record captures who initiated the task, which agent acted, the objective it was given, the systems and documents it touched, the permissions checked, the actions proposed or completed, whether approval was required, and the final outcome.

Make it real-time

Reuse existing controls — and verify continuously

The better approach is to bring the controls organizations already rely on into the agent experience itself, and expand them where the use case and risk profile demand. At the foundation, identity and access management, data classification, retention policies, legal holds, incident response, and audit logging should keep applying — an agent only makes their consistent application more important.

Before deploy

Verify up front

Check permissions, access limitations, and sharing restrictions, then test — especially where the agent takes consequential or high-risk actions.

After deploy

Re-verify periodically

Policies and periodic reviews can’t supervise every action of an autonomous system, so verification must run in real time and repeat on a schedule.

Trust as a strategic advantage

The organizations that succeed with autonomous agents will be the ones that can show how those agents are governed, what they’re permitted to do, and how their actions can be understood when questions arise. In the next phase of enterprise AI, trust won’t slow innovation down — it’s what makes innovation sustainable.
