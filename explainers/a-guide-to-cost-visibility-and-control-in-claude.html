Seeing — and controlling — what Claude costs

Businesses run Claude across thousands of employees and inside their own applications, and cost matters to all of them. Anthropic’s guide walks IT admins through the controls that exist today: think in cost-per-outcome, match the model to the work, cap the spend, and pull the API levers that quietly cut a production bill.

The idea in five lines

  • Measure cost-per-outcome — not tokens: ask what the work would have cost without AI, and whether the task needs judgment or is just high-volume.
  • Match the model to the work — Fable for the hardest problems, Opus for long-horizon and coding, Sonnet for everyday analysis, Haiku for routine volume — with effort dials and the advisor tool.
  • Admin controls for Enterprise — access gating, model entitlements and defaults, and hard spend caps that bind immediately.
  • Observe usage three ways — the analytics dashboard, the Analytics API into BI and finance systems, and analytics chat you can ask in plain language.
  • API levers stack — prompt caching (about 10% of the input rate on hits), batch processing at half price, the effort parameter, and the advisor strategy.
So what for you

If you’re rolling Claude out, start with one team and watch a month of real usage before you set caps. Default most people to a mid-tier model like Sonnet, entitle only your hardest work to frontier models, and reconcile the exported usage data against your invoice so cost stays legible as you expand.

The reframe

Cost-per-outcome, not cost-per-token

The most useful measure of AI’s cost is the outcome it produces, not the tokens it burns. Two questions clarify almost any project: what would this work have cost without AI — in resources, in time, or in never attempting it at all — and is the model doing work that’s genuinely hard and needs judgment, or work that’s merely large?

Put a cheap model on complex reasoning and it often costs more — it burns tokens on retries and needs human correction. Put a frontier model on basic document processing and you pay for capability the task never uses.

The first question only your business can answer. The second you address by matching the model to the work — and Claude’s family is built to give you that choice.

Many organizations use several models on the same project. An insurer might put a frontier model beside an adjuster evaluating a complex commercial claim, while Haiku tags and triages the documents feeding into it — each token spent where its capability is actually needed.

Controls for Claude Enterprise

Gate access, control models, cap spend

Where Claude runs as a product for employees, the controls sit with the admin. Work through them roughly in order — it’s hard to set a sensible limit before you’ve seen a month of real usage.

Access gatingRoll out gradually

Decide which groups and custom roles can use products like Claude Code and Cowork — not an all-at-once switch. Start with one team, watch the results, and expand department by department.

Model controlsEntitlements + defaults

Entitlements set which models a team can reach; defaults set which model a new conversation starts on. Entitle your hardest work to the most capable models and default everyone else to Sonnet.

Hard spend capsBind immediately

Place ceilings on the whole org, individual users, or a group (where each member gets the limit). Set them once you know your baseline; caps take effect right away.

Admins can also automate review of spend-limit-increase requests, flag members close to their limit, and surface members whose usage is changing fast.
