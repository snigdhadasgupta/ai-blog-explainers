The AI-Native SDLC Playbook

AI now writes code at a speed unthinkable a year ago — but the approvals, reviews, and handoffs around it haven’t changed. Anthropic’s Applied AI team lays out how to rebuild the software development lifecycle so the human-speed steps stop stalling the gains.

The idea in five lines

  • Code is no longer the bottleneck — when agents write most of the diff, the constraint moves to plan, review, and deploy, which still run at human speed.
  • Old controls stop matching reality — reviewing every line by hand can’t keep pace, and exceptions still route through weekly committees.
  • The process becomes a loop — six stages (plan, design, build, test, deploy, maintain) with AI embedded and automated handoffs between them.
  • Every stage commits an artifact — intent.md, spec.md, plan.md, the diff and its tests, the PR — and the next stage begins by reading it.
  • The commit chain is the audit trail — who asked for what, what the agent produced, and who approved it — with humans accountable at the gates.
So what for you

If your teams have adopted agentic coding but feel “stuck”, look left and right of the build step: the payoff comes from transforming plan, review, and deploy too — start by making each stage end with a committed, machine-readable artifact the next stage can act on.

The shift

Build got fast; everything around it didn’t

The traditional SDLC — plan, design, build, test, deploy, maintain — was engineered for an era when writing and implementing code was the most expensive stage. PRDs, estimation rituals, and security reviews all existed to force alignment during weeks or months of build work. Now that agents like Claude Code collapse the build phase to hours, three things become true.

1

The bottleneck moves

To the steps left and right of build — plan, review/test, and deploy — which still run at human speed.

2

Controls stop matching reality

Reviewing each line by hand made sense when a person wrote it; it can’t keep up once agents write most of the diff.

3

Governance costs climb

Exceptions still route through meetings and committees that convene weekly or monthly, throttling throughput.

Security teams are sized for human output — so when agents multiply code, either the review queue builds or code ships under-reviewed. A regulated org can accept neither.

Why it matters

From a linear flow to a governed loop

The AI-native SDLC keeps the old control objectives but changes the enforcement. Instead of a linear flow with clunky handoffs, the process becomes a loop with AI embedded at each point and automated triggering of the next stage. Humans remain accountable for every decision that requires judgment — their attention shifts to the gates, reviewing what the agent flagged rather than starting each stage from scratch.

Stage by stage

Where the work shifts in each phase

The through-line is the committed artifact: each stage writes one to version control and the next stage begins by reading it. Early stages favor human-and-machine-readable .md files; from build onward, the artifact is code and its records.

Planintent.md

Claude synthesizes pain points straight from the sources into an intent.md that is human-readable and machine-actionable — replacing committee-gathered requirements.

Designspec.md

Requirements and design compress into one working session with an agent, guided by standards encoded as skills and versioned in git.

Builddiff + tests

Tests and code are AI-generated; institutional knowledge lives as versioned, machine-readable CLAUDE.md files and skills.

Testcontinuous evals

Continuous evaluations are woven through implementation rather than bolted on as QA gates at stage boundaries.

DeployPR + hooks

Layers of agentic review, with human review reserved for regulated and critical code; governance is enforced as the AI acts, with hooks as approval gates.

Maintainnext intent.md

Agents monitor live deployments; any breached control band is diagnosed and written back into the loop as a new intent.md.

Adoption is modular: you can transform stages in any order based on your bottleneck. First you prompt each step by hand; the end state is a loop where each accepted artifact fires the next gate — an accepted intent.md triggers design, an approved spec.md triggers plan mode, a merged PR triggers the pipeline.

Where to start

Pick the stage that’s actually your constraint — often review or deploy — and make it end with a committed artifact the next stage can read. Concentrate human attention at the gates, and let each accepted artifact trigger the next play.
