Maximizing the Value of Your Claude Code Sessions

With agentic coding tools, the same fix can cost wildly different amounts. Anthropic’s guide to running lean sessions — so the tokens you spend go toward the thing you actually asked for, not the ten files Claude dragged along.

The idea in five lines

  • Same task, different price — with agentic coding you pay for inference, so a lean session and a rambling one can cost very differently for the identical fix.
  • Three things set a token’s price — which model runs it, whether it’s input or output (output is ~5× input), and whether it was cached (cache reads are 0.1× input).
  • Don’t break the cache mid-run — switching /model, /effort, or fast mode re-prefills the whole conversation at full price — do it at the start or right after /clear.
  • Everything you load re-sends — files read and command output stay in context every turn after, so @-mention files, quiet noisy commands, and offload big jobs to subagents.
  • Keep sessions short and scoped — /clear between tasks, /compact before a break (while it’s still cached), and /context once to trim what’s loaded.
So what for you

Even if you’re not writing code, the lesson generalizes: with usage-priced AI, cost is a function of how you run the session, not just what you ask. Start each task fresh, attach only what’s needed, and clear context between jobs — the habit saves real money at scale.

Why this is new

The task now has a price of its own

Until recently, your editor cost the same whether you fixed one test or fifty that afternoon — an individual task didn’t really have a price of its own. Agentic tools changed that: you pay for inference, the GPU time it takes to run the model over your tokens, so the same completed task can cost different amounts depending on how you run it.

In one session Claude reads the test and the file it covers and is done in a few turns. In another it greps around, reads a dozen files on the way to the same two, and every turn drags along everything read since this morning.

Being efficient with tokens doesn’t mean using fewer of them — it means making sure the ones you do use go toward the thing you actually asked for.
What sets the price

Three levers on every token

Figure 1 · What decides a token’s cost
Model

Bigger is pricier

A larger model does more work on every input and output token, and multiplies everything below it. Use a big model for genuinely hard or ambiguous work, a smaller one for routine grunt work.

Input vs output

Output is ~5×

Prefill reads your request and context (input); decode writes thinking, tool calls, and text one token at a time (output). Per token, output costs roughly five times input.

Prompt caching

Reads are 0.1×

If a request starts with the same tokens as one the server just saw, that prefix is loaded, not recomputed. Cache reads cost 0.1× input; writes up to 2×, once.

The cache

How to not throw the cache away

Claude Code manages the prompt cache on every request — there’s nothing to turn on. But the cache has to match from the very start of the request forward, and requests always go out in the same order: tool definitions, system prompt, then the conversation. Change anything near the front and everything behind it gets prefilled again at full price.

Cheap moments

Switch at the edges

The start of a session or right after a /clear is when changing /model or /effort costs almost nothing — the conversation behind it is short or empty.

Expensive moments

Mid-conversation switches

/model, /effort, and fast mode are part of the cache key, so flipping them mid-run re-prefills the whole conversation. /compact rewrites it; prefer /rewind to trim the last few turns for free.

What fills the context

Everything you load re-sends every turn

Nothing gets sent just once. Every file Claude reads and every command it runs is appended to the conversation and re-sent on every turn after, for the rest of the session. It’s cached, so cheap — but cheap isn’t nothing, and it’s room the model has to think around each turn.

@-mention

Attach, don’t hunt

Referencing a file by @-mention attaches it to your first message — no Read call, no grep to find it. Mention it once; it stays in context.

Quiet commands

Tame noisy output

A test runner printing 400 passing lines lands under the 30k-char file threshold and sticks around every turn. Add quiet flags in CLAUDE.md, or run it in a subagent.

Subagents

Offload noisy jobs

A subagent gets its own context and returns only its answer — ideal for going through a log. Give recurring noisy jobs their own definition on a cheaper model.

Where to look first

Four things are worth watching, roughly in order of cost: which model you run, how long a single session gets, noisy command output that lingers, and cache-busting switches made mid-conversation. Keep sessions short, scoped, and deliberate.
