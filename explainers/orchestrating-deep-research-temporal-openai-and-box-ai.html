Orchestrating Deep Research With Temporal, OpenAI, and Box AI

A durable research agent that turns one cross-market question into multilingual retrieval, cited synthesis, localized briefs, and a governed research pack in Box — with recoverable state so failures don’t lose work.

The idea in five lines

  • One question, four markets — compare how audiences discover indie films in France, Japan, Brazil, and Poland, in each market’s own language and sources.
  • Retrieval, not translation — searching only in English and translating the answer misses the local evidence that should shape it.
  • Three systems, clear jobs — OpenAI plans, searches, and synthesizes; Temporal holds state and coordinates; Box governs and stores the artifacts.
  • Durable means recoverable — completed steps replay from event history, so a restart resumes instead of redoing every model call.
  • Retry-safe, permission-bound — stable Workflow IDs plus Box versioning prevent duplicates; Box AI answers only over selected files the user can access.
So what for you

For long-running agents, the model is the easy part. What makes one production-worthy is durable state, partial-result handling, retry-safe writes, and answers grounded in permissioned content — design for those before you scale.

The problem

A prompt isn’t a research process

Picture a film distributor releasing an indie title in France, Japan, Brazil, and Poland. The useful evidence — film-institute reports, festival programs, local streaming data, creator communities — lives in four languages and four information ecosystems. Search only in English and translate the answer, and you produce a polished brief that misses the local evidence that should have shaped it.

So the multilingual angle is part of retrieval, not just presentation. And once one question fans out into concurrent searches, synthesis, localized briefs, and uploads — each crossing a network boundary — you’re no longer writing a prompt. You’re running a distributed workflow with state and side effects.

Durable execution preserves completed work and makes the conditions for continuing explicit — a more useful definition of agent durability than “retry everything.”

The design

Three systems, one clear job each

Figure 1 · Division of labor
Reason

OpenAI

Plans the investigation, generates per-market queries, searches current web sources, synthesizes the cited master report, and writes localized briefs.

Orchestrate

Temporal

Stores execution state and coordinates dependencies, concurrency, retries, and failure semantics. Event history is the durable record of what happened.

Govern

Box & Box AI

Stores versioned, permissioned artifacts, then answers over deliberately selected internal files — cited, and grounded in the authenticated user’s access.

Research languages control what gets collected; output languages control the briefs written afterward. Keeping them separate stops presentation choices from quietly narrowing the source base.

Resilience

Parallel search without losing useful work

Market searches run concurrently — fan-out, then fan-in. If one search fails terminally, the workflow keeps the successful evidence from every other market and continues with partial results. Only if no search produces evidence does it stop with a non-retryable NO_SEARCH_RESULTS error, rather than asking the model to invent a report from an empty context.

Typed results matter too: each search returns a structured object carrying the query, source URLs, findings, and citations. The synthesis step receives evidence and citations directly instead of reverse-engineering them from text produced by the previous call. Every stage has a contract.

Side effects

Making Box publication retry-safe

Temporal may run an activity more than once, so uploads must be safe to repeat. Every output filename contains the stable Workflow ID; before uploading, the Box activity checks the folder for that exact name. A repeat therefore writes a new version of the intended file rather than a near-duplicate copy. Temporal supplies durable retries; the application still has to make the external write safe — stable IDs as the correlation key, Box file versioning as the duplicate-resistant behavior.

Nuance

Retry-safe, not idempotent

A retry after a successful-but-unacknowledged upload can still add a version. A production build should prevent Workflow-ID reuse and persist the returned Box file ID so later attempts address the object directly.

Boundary

Permission-bound answers

The final Box AI step accepts one report plus up to 24 deliberately selected internal files. It doesn’t discover documents or broaden access — the service account must already have permission.

For long-running agents, the model is the easy part

What makes an agent production-worthy is durable state, partial-result handling, retry-safe writes, and answers grounded in permissioned content. Design for those before you scale — a useful agent has to survive delays and failures and leave evidence people can inspect.
