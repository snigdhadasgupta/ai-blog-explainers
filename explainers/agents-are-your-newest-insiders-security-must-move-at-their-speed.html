Agents are your newest insiders

An agent’s usefulness comes from its access to your data, apps, and tools — and that access is exactly what makes it an insider risk. Microsoft’s argument: govern every agent as an insider, with its own identity, zero standing access, a sandboxed runtime, and controls that live outside the model and adapt as risk changes.

The idea in five lines

  • Agents are insiders — their value comes from access to company data, apps, and tools, and that same access is what creates insider risk.
  • The governing principle — surround non-deterministic intelligence with deterministic controls, independent evidence, and containment boundaries the model can’t reach.
  • Four continuous responsibilities — Know, Contain, Protect, Adapt — run together, not as phases: “evidence changes risk, risk changes policy, policy changes what the agent can do.”
  • Least privilege by default — an agent begins with no authority and gets only what the task needs, for only as long as it needs; higher-impact actions require verified human approval.
  • Respond in graduated steps — reduce permissions, keep reads but block writes, narrow data, shorten access, or isolate the runtime — executed at machine speed.
So what for you

Before you scale agents, give each one its own identity rather than a borrowed user login, start it at zero standing access, and make sure the controls watching it live outside the model — so a compromised or manipulated agent can’t switch them off. Attribution (“what did the agent do, vs. the person?”) depends on that separate identity.

Why this frame

Capable, trusted, and not always right

Agents aren’t malicious — they’re capable tools users grant access to important systems. But they can make mistakes, be manipulated by untrusted content, or be compromised; their outputs vary, context shifts, and plans evolve mid-task. And they run continuously, at machine speed and scale. That combination — broad access plus non-determinism plus speed — is what makes “insider” the right mental model.

“The most trustworthy agentic system will not be the one with the model we trust most… We must separate the supply of intelligence from the authority over it.”

The controls

What makes it concrete

Know

First-class agent identity

Every agent gets its own identity distinct from its user or sponsor (Microsoft Entra Agent ID), so the enterprise can tell what a person did from what an agent did on their behalf. Discovery now spans 35 more local agent types — 60 total, including Claude Code, OpenAI Codex, and GitHub Copilot.

Contain

Sandbox + mediated actions

Run the model and harness in a controlled environment (Microsoft Execution Container), not with full device access. An agent shouldn’t call any tool, API, MCP server, or other agent it can find — those paths are mediated and inspected. “If compromised, it shouldn’t be able to disable the controls watching it.”

Adapt

Dynamic, graduated response

Dynamic Agent Risk fuses identity, data, endpoint, network, and activity signals into a live score; Dynamic Conditional Access responds in degrees — reduce permissions, block writes, narrow resources, shorten access, or at the extreme isolate the runtime.

Least privilege is the default posture: an agent “should begin with no authority and receive only what it needs for the approved task, for only as long as the task requires.” Org-wide policy sets the outer boundary — an agent can never obtain authority its user lacks — and consequential actions require provable human approval.

A worked example

The expense agent that meets a prompt injection

Scenario

Nothing changed but the risk

A benign expense-approval agent reads submissions, checks policy, and approves routine reimbursements. It then meets a prompt injection buried in an external document. Its configuration is unchanged — but its risk is not.

Response

Proportionate, not binary

Keep the safe reads, block the writes, narrow the resources it can touch, require human approval, or isolate and stop execution — scaled to the risk, and carried out by Guardian Agents at machine speed while people keep control of objectives.

The controls named — Project Perception, Microsoft Agent 365, Entra Agent ID, Dynamic Permissions, Dynamic Conditional Access — are Microsoft’s; the post gives no pricing or GA dates, and “the model cannot be its own security boundary.”

What to do before you scale

Inventory every agent — including partner-built and locally introduced ones — into one registry; give each a first-class identity; start them at zero standing access and grant task-scoped, time-bound permissions; and keep the controls that observe and constrain them outside the model, adapting as risk changes.
