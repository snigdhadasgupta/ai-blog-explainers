MCP goes stateless

The fifth spec of the Model Context Protocol — MCP 2026-07-28 — moves the standard to a stateless request/response core, graduates MCP Apps and Tasks as versioned extensions, and aligns auth with real enterprise identity systems. Support is rolling out across Claude products.

The idea in five lines

  • MCP is now the standard — 400M+ monthly SDK downloads (4x this year) and 950+ connectors listed in Claude’s directory.
  • Stateless core — the protocol moves from a bidirectional stateful session to plain request/response, so servers run on serverless and edge infrastructure.
  • Extensions graduate — MCP Apps (interactive UIs) and Tasks (long-running work) ship under a versioned framework, so new capabilities do not fork the core.
  • Auth is hardened — authorization now aligns with production OAuth 2.0 and OIDC, connecting to Entra or Okta without workarounds.
  • Rolling out in Claude — alongside enterprise-managed auth, connector observability, and MCP tunnels for private-network servers.
So what for you

If your team relies on custom connectors or is planning to publish one, the stateless spec makes them cheaper to host and simpler to scale — and enterprise-managed auth means IT can provision a connector once for the whole org instead of every user authorizing it. Worth flagging to whoever owns your integrations roadmap.

Why this release matters

The plumbing that connects agents to your tools grew up

MCP is the open standard that lets AI agents talk to applications and data — the reason a single assistant can reach your files, tickets, meetings, and finance systems. This release is one of the most significant to date because it changes how MCP servers are built and run, not just what they can do. A stateless core removes session management, so a connector becomes an ordinary HTTP workload that any serverless or edge platform can host and autoscale.

The stateless core, standardized extensions, and hardened auth will help developers bring more applications to Claude with a lower-friction, more consistent end-user experience.

The three changes

What actually changed in the spec

Core Stateful sessions → stateless request/response
Servers no longer hold a live bidirectional connection. Each call stands alone, so MCP servers deploy on serverless and edge infrastructure and scale as adoption grows — with no session state to manage.
Extend MCP Apps + Tasks become versioned extensions
Interactive UIs (Apps) and long-running work (Tasks) now ship under a formal, versioned extensions framework — a defined path to add capability without changing the core protocol.
Auth Authorization aligns with OAuth 2.0 / OIDC
Auth now matches production identity deployments, so MCP servers connect to enterprise systems like Microsoft Entra or Okta without custom workarounds.

Advancing MCP in Claude

The features that ride on the new spec

Apps

Interactive UI in the conversation

MCP Apps let a server render UI directly in chat, so users can see what a connector is doing and work with it inline — no tab switching.

Auth

Enterprise-managed auth

Admins provision connectors for the whole organization through their identity provider. Authorize once; users inherit access through existing IdP groups with zero-touch setup.

Observability

Dashboards for connector builders

Published connectors get a dashboard to track adoption, diagnose errors and latency, and break usage down by Claude product surface.

Tunnels

Private-network servers (research preview)

MCP tunnels connect Claude to servers inside a private network — no inbound firewall rules, public endpoints, or IP allowlisting on the origin.

Who is already building on it

Ecosystem partners on the beta

Companies across the ecosystem built on the spec during beta. Figma cites the stateless architecture scaling with growing usage while Apps, Tasks, and enterprise auth keep design and code in one flow. Intuit points to the stateless core plus extensions for building agentic experiences at enterprise scale across 100 million consumers and businesses. Netlify calls the stateless core the change that makes MCP “a first-class HTTP workload with no session management to work around.” Xero, PostHog, and Zoom echo the same theme: less complexity to manage, easier to deploy and scale on standard HTTP infrastructure.

What to do about it

If you own connectors, plan to move servers onto the stateless spec to cut hosting complexity, and evaluate enterprise-managed auth so IT provisions connectors org-wide. Explore the spec and SDKs now; support is rolling out across Claude products soon.
